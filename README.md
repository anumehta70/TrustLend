# 🏦 TrustLend — Undercollateralized Micro-Loans on Stellar Soroban

**TrustLend turns a borrower's verifiable, tamper-proof Stellar payment history into a credit score a Soroban contract can lend against, unlocking credit without a traditional bureau file.**

Gig workers, small farmers, and micro-merchants in emerging markets often have steady income but no formal credit history — locking them out of loans or pushing them toward predatory local lenders. TrustLend bridges this gap by scoring on-chain transaction history, allowing undercollateralized lending (10%–50% collateral) directly via a decentralized liquidity pool.

## 🌟 Key Features

1. **On-Chain Credit Scoring**: `get_credit_score` derives a 300–1000 score from your payment frequency, volume, and repayment history, fully calculated via Soroban logic.
2. **Undercollateralized Lending**: Based on the credit score, users only need to post 10%–50% collateral instead of the standard 100%+ seen in DeFi.
3. **Decentralized Liquidity Pools**: Lenders deposit stablecoins into a pool (`lp_deposit`) and earn a share of the interest generated by active loans.
4. **Automated Repayment & Defaults**: Borrowers repay on-chain (`repay`). Overdue loans can be settled by a keeper (`mark_default`), which seizes collateral and applies a severe score penalty.
5. **Robust Dashboard UI**: Built with React and Vite. Features a beautifully designed "field ledger" aesthetic, seamless wallet connection via Freighter, and real-time syncing.

### 3. Future Roadmap: Evolving TrustLend (Next Phase)
Based on the broader feedback collected from our 50+ users in the Google Sheet, we have identified key areas for our next phase of development:
- **Fiat On/Off Ramps**: Multiple users requested an easier way to move between local currency and Stellar USDC. We plan to integrate MoneyGram Access for seamless global cash deposits and withdrawals.
- **Credit Score as a Service**: Users loved the on-chain scoring logic. We plan to decouple the `get_credit_score` module into a standalone Soroban oracle that other dApps can query.
- **Hardware Wallet Support**: Advanced users requested Ledger integration, which we will prioritize in our next frontend update.
- **Mobile Application**: While our web app is fully mobile-responsive (as seen in the screenshots), users frequently asked for a dedicated React Native mobile app for easier everyday borrowing.

## ⚙️ How it works

1. **Payment indexing.** An off-chain indexer watches a borrower's wallet on Horizon for confirmed inbound payments and records them into the contract's on-chain payment ledger via `record_payment`.
2. **Scoring.** The contract calculates a dynamic credit score, loan ceiling, and minimum collateral ratio based on the updated payment ledger.
3. **Lending.** Borrowers post the required collateral and draw a loan (`request_loan`) sized against their score.
4. **Repayment.** Full repayment releases collateral and improves the score for future loans.

## 🚀 Why Stellar?

Stellar settles in ~5 seconds for fractions of a cent, which is what makes loans this small (think $10–$50) economically viable — gas alone would exceed the loan value on most other chains. The same low-fee payment rails that make Stellar useful for gig payouts and marketplace settlements are also the income signal TrustLend scores against. The credit primitive falls directly out of Stellar's existing strengths rather than requiring a separate off-chain identity.

- **Writing tests for contracts**: Extensive Rust unit tests covering lending pools, credit scoring bounds, collateral requirements, and default scenarios. The CI strictly enforces passing tests before any merge.
- **Production-ready architecture practices**: Decoupled smart contracts, a dedicated Express/TypeScript backend for indexing, and MongoDB persistence.

## 🏗️ Architecture

```
contracts/trustlend/   Soroban contract: pool, payment ledger, scoring, loans
backend/               Express/TypeScript API: indexer, score/loan routes, Mongo
frontend/              React/Vite dashboard: borrower + lender flows, Freighter
```

**Data flow:** borrower's Stellar payments → Horizon → indexer → `record_payment` on-chain → `get_credit_score` → borrower requests a loan signed with Freighter → contract disburses from the pool → backend indexes the loan → borrower repays on-chain → score updates.

## 💻 Running locally

### 1. Contract
See `contracts/trustlend/README.md` for build/test/deploy steps. You need a Rust toolchain with the `wasm32-unknown-unknown` target and `soroban-cli`. Run `cargo test` to execute the test suite.

### 2. Backend
```bash
cd backend
cp .env.example .env   # fill in CONTRACT_ID, TOKEN_CONTRACT_ID, INDEXER_SECRET
npm install
npm run dev
```
Requires a MongoDB instance (`MONGODB_URI`) — a local `mongod` or a free Atlas cluster.

### 3. Frontend
```bash
cd frontend
cp .env.example .env   # fill in VITE_CONTRACT_ID, VITE_TOKEN_CONTRACT_ID
npm install
npm run dev
```
Open the local URL and use the [Freighter](https://freighter.app) browser extension set to Testnet to connect a wallet.
